1"""Core methylation extraction functions for bam2tensor. 

2 

3This module contains the main function for extracting methylation data from 

4BAM files: extract_methylation_data_from_bam(). This function reads aligned 

5bisulfite-sequencing (BS-seq) and enzymatic methylation sequencing (EM-seq) 

6reads and generates a sparse matrix representation of methylation states at 

7each CpG site, with one row per sequenced DNA fragment. 

8 

9The extraction process: 

10 1. Iterates through each chromosome in the genome embedding 

11 2. For each aligned read that passes the read filters: 

12 a. Determines which bisulfite strand the fragment derives from 

13 b. Identifies the CpG sites whose informative base the read covers 

14 c. Extracts the methylation state at each of those CpGs, keeping 

15 a call only where the read shows an intact CpG on a base of 

16 sufficient quality 

17 3. Combines the two mates of a read pair into a single fragment 

18 4. Builds a sparse COO matrix with one row per fragment 

19 

20Methylation State Encoding: 

21 - 1: Methylated (cytosine remained as C after bisulfite treatment) 

22 - 0: Unmethylated (cytosine converted to T by bisulfite treatment) 

23 - -1: No usable call. The fragment covers the CpG, but the read does 

24 not show an intact CpG there (an indel, SNV or other unexpected 

25 base at either base of the CpG), the base carrying the call is 

26 below the minimum base quality, the CpG lies in the masked 3' end 

27 of the fragment (opt-in), or the two mates of a pair disagree. 

28 

29Strands and the informative base: 

30 A fragment derives from either the top or the bottom strand of the 

31 original DNA, and both mates of a proper pair report on that same 

32 strand. BAM 

33 stores every read in top-strand orientation, so for a CpG whose C is at 

34 reference position p: 

35 

36 - a top-strand fragment carries the call on the C, at p 

37 (C = methylated, T = unmethylated); 

38 - a bottom-strand fragment carries it on the G, at p + 1 

39 (G = methylated, A = unmethylated). 

40 

41 Each read is therefore decoded at whichever of the two bases is 

42 informative for its fragment's strand, whatever the read's own alignment 

43 orientation. 

44 

45Supported Aligners: 

46 The module supports BAM files from aligners that provide strand information: 

47 - Bismark: Uses the XM call string (Z=methylated CpG, z=unmethylated 

48 CpG) and the XG tag (CT=top strand, GA=bottom strand) 

49 - Biscuit: Uses the YD tag (f=top strand, r=bottom strand) 

50 - bwameth: Uses the YD tag (f=top strand, r=bottom strand), as Biscuit 

51 - gem3/Blueprint: Uses the XB tag (C=top strand, G=bottom strand) 

52 

53Example: 

54 >>> # xdoctest: +SKIP 

55 >>> from bam2tensor.embedding import GenomeMethylationEmbedding 

56 >>> from bam2tensor.functions import extract_methylation_data_from_bam 

57 >>> 

58 >>> # Create genome embedding 

59 >>> embedding = GenomeMethylationEmbedding( 

60 ... genome_name="hg38", 

61 ... expected_chromosomes=["chr1", "chr2"], 

62 ... fasta_source="reference.fa", 

63 ... ) 

64 >>> 

65 >>> # Extract methylation data 

66 >>> result = extract_methylation_data_from_bam( 

67 ... input_bam="sample.bam", 

68 ... genome_methylation_embedding=embedding, 

69 ... quality_limit=20, 

70 ... ) 

71 >>> 

72 >>> print(f"Extracted {result.matrix.shape[0]} reads, {result.matrix.nnz} data points") 

73"""

94 

95 Attributes: 

96 matrix: Sparse COO matrix of shape (n_fragments, n_cpg_sites) with 

97 methylation states: 1 (methylated), 0 (unmethylated), -1 

98 (no data). Each row is one sequenced DNA fragment: the two 

99 mates of a read pair combined, or a single read. 

100 tlen: 1-D numpy array of shape (n_fragments,) containing the 

101 length of each fragment (the absolute BAM TLEN). 0 for 

102 single-end reads or reads with unmapped mates. 

103 stats: Counts describing what the extraction saw and discarded, 

104 for quality control (the CLI stores them in the output file's 

105 metadata). Keys: 

106 

107 - ``reads_used``: reads that passed every read filter 

108 (mapping quality, flags, proper pair), whether or not they 

109 cover a CpG. 

110 - ``reads_dropped_improper_pair``: reads skipped because 

111 they are paired but not flagged as a proper pair. 

112 - ``reads_without_md``: reads the non-converted filter could 

113 not evaluate for lack of an ``MD`` tag. 

114 - ``fragments_from_two_mates``: fragments in which the calls 

115 of two mates were combined (counted before the 

116 fragment-level filters). 

117 - ``cpg_observations``: CpGs decoded, counted per read 

118 (before the two mates of a pair are combined). 

119 - ``cpg_not_intact``: observations stored as ``-1`` because 

120 the read does not show an intact CpG there. 

121 - ``cpg_reference_mismatch``: how many of those disagree with 

122 the reference in a way a wrong strand tag cannot explain 

123 (the count behind the reference check). 

124 - ``cpg_low_base_quality``: observations stored as ``-1`` 

125 because the base carrying the call is below the minimum 

126 base quality. 

127 - ``cpg_masked_3prime``: calls stored as ``-1`` because they 

128 lie in the masked 3' end of their fragment (counted per 

129 fragment, after the mates are combined). 

130 - ``strand_checks`` and ``strand_contradictions``: the 

131 strand-tag check (CpGs examined, and how many contradict

149def count_non_cpg_retained_xm(xm_tag: str) -> int: 

150 """Count retained non-CpG cytosines in a Bismark XM methylation string. 

151 

152 Bismark's ``XM`` tag encodes per-base methylation context. Uppercase 

153 letters indicate a cytosine that remained as ``C`` in the read 

154 (i.e., was *not* converted by bisulfite/EM-seq treatment). ``H``, 

155 ``X`` and ``U`` correspond to retained cytosines in CHH, CHG and 

156 unknown-context positions respectively. A high count of these on a 

157 single read is a strong signal of incomplete conversion. 

158 

159 Args: 

160 xm_tag: The value of a read's Bismark ``XM`` tag. 

161 

162 Returns: 

163 The count of ``H``, ``X`` and ``U`` characters in ``xm_tag``. 

164 

165 Example: 

166 >>> count_non_cpg_retained_xm("..Z..hhh..HHH..z..") 

167 3 

168 """ 

169 return xm_tag.count("H") + xm_tag.count("X") + xm_tag.count("U")

172def count_non_cpg_retained_reference( 

173 aligned_segment: pysam.AlignedSegment, 

174 is_reverse_parent_strand: bool, 

175 cpg_positions: Container[int] | None = None, 

176) -> int: 

177 """Count retained non-CpG bases validated against the reference. 

178 

179 For a correctly bisulfite- or EM-seq-converted read, every 

180 non-CpG cytosine on the parent strand should have been converted. 

181 On the forward-parent strand that means every non-CpG ``C`` in the 

182 reference should appear as ``T`` in the read; on the reverse-parent 

183 strand every non-CpG ``G`` should appear as ``A``. Positions where 

184 the read still carries the unconverted base *and* the reference 

185 genuinely has a ``C``/``G`` (i.e., the mismatch is not a SNP) count 

186 as retained. 

187 

188 This is a port of the logic in 

189 ``nebiolabs/mark-nonconverted-reads``, re-using the read's existing 

190 ``MD`` tag (via :py:meth:`pysam.AlignedSegment.get_aligned_pairs` 

191 with ``with_seq=True``) instead of requiring a separate reference 

192 FASTA. 

193 

194 Which cytosines are in CpG context — and so exempt — is best taken 

195 from the CpG index via ``cpg_positions``. Without it, the context is 

196 inferred from the neighbouring reference base as reconstructed from 

197 the read, which cannot see a neighbour lying just outside the 

198 alignment: a methylated CpG cut by the end of the read is then 

199 counted as a retained non-CpG cytosine. 

200 

201 Note: 

202 The count is only as good as the ``MD`` tag. bwa-meth writes 

203 ``MD`` relative to its bisulfite-converted reference. For the 

204 directional libraries bwa-meth is designed for, that gives the 

205 exact count, with one blind spot: a read ``C`` over a reference 

206 ``T`` (or ``G`` over ``A``) is a SNP that conversion makes 

207 invisible, so it is counted as retained. For a non-directional 

208 library aligned with bwa-meth the tag does not describe the 

209 read as stored, and retained cytosines are undercounted. 

210 

211 Args: 

212 aligned_segment: A pysam aligned read. Must carry an ``MD`` 

213 tag. bwa-meth writes one; gem3 does not for bisulfite 

214 alignments, so its reads cannot be evaluated unless the tag 

215 is added afterwards (for example with ``samtools calmd``). 

216 is_reverse_parent_strand: ``True`` if the read derives from the 

217 reverse (OB/CTOB) bisulfite parent strand, ``False`` for 

218 the forward (OT/CTOT) strand. 

219 cpg_positions: 0-based reference positions of the ``C`` of 

220 every CpG the read touches, including a CpG whose ``C`` or 

221 ``G`` lies just outside the alignment. If ``None``, CpG 

222 context is inferred from the read's own reconstruction of 

223 the reference. 

224 

225 Returns: 

226 The number of reference-validated retained non-CpG 

227 cytosines (or guanines, for the reverse parent strand). Returns 

228 ``0`` when the read has no sequence or no ``MD`` tag is present. 

229 """ 

230 if aligned_segment.query_sequence is None: 230 ↛ 231line 230 didn't jump to line 231 because the condition on line 230 was never true

231 return 0 

232 

233 try: 

234 pairs = aligned_segment.get_aligned_pairs(matches_only=True, with_seq=True) 

235 except ValueError: 

236 # MD tag missing — cannot validate against reference. 

237 return 0 

238 

239 # Map ref_pos → reference base (uppercase) for CpG-context lookup. 

240 # matches_only=True guarantees query_pos, ref_pos, ref_base are all set. 

241 ref_pos_to_base = {rpos: rb.upper() for _, rpos, rb in pairs} 

242 

243 # On match, pysam returns ref_base uppercase (query matches ref). 

244 # On mismatch (SNP), it returns lowercase. We only care about matches 

245 # where ref is C/G — those are genuine retained, non-converted bases. 

246 target = "G" if is_reverse_parent_strand else "C" 

247 

248 count = 0 

249 for _, rpos, ref_base in pairs: 

250 if ref_base != target: 

251 # Not a match, or ref is not C/G. This rejects SNPs (lowercase) 

252 # and converted positions (read has T/A, match has different base). 

253 continue 

254 # Exclude CpG context. 

255 if cpg_positions is not None: 

256 # From the CpG index: exact, even when the other base of the CpG 

257 # lies outside the read. On the reverse strand the retained base 

258 # is the G, one position right of the CpG's C. 

259 if (rpos - 1 if is_reverse_parent_strand else rpos) in cpg_positions: 

260 continue 

261 elif is_reverse_parent_strand: 

262 # Reverse strand: previous reference base is C. 

263 if ref_pos_to_base.get(rpos - 1) == "C": 

264 continue 

265 else: 

266 # Forward strand: next reference base is G. 

267 if ref_pos_to_base.get(rpos + 1) == "G": 

268 continue 

269 count += 1 

270 

271 return count

274def is_em_overconversion_read( 

275 read_cpg_states: list[int], 

276 min_cpgs: int, 

277) -> bool: 

278 """Identify reads flagged as EM-seq fragment-level over-conversion. 

279 

280 Loyfer et al. (bioRxiv 2026.03.24.713040) report that EM-seq 

281 produces a reproducible ~1–2.5% of multi-CpG fragments that appear 

282 fully unmethylated across every covered CpG, driven by failed TET 

283 protection and subsequent APOBEC hyper-conversion of an entire 

284 molecule. At constitutively methylated loci these reads are purely 

285 technical. Without a per-region methylation prior, the simplest 

286 correction consistent with their observation is: drop reads whose 

287 CpG calls are all unmethylated *and* number at least ``min_cpgs`` 

288 (the paper's Fig. 1C regime where the artifact diverges clearly 

289 from WGBS). 

290 

291 CpGs without a usable call (``-1``) are left out of the decision 

292 altogether: they are neither evidence of methylation nor counted 

293 towards ``min_cpgs``. Otherwise a single low-quality base would 

294 shield an otherwise fully unmethylated fragment from the filter. 

295 

296 This heuristic also drops genuinely fully-unmethylated biological 

297 fragments, so callers should opt in only when the downstream 

298 application can tolerate that trade-off. 

299 

300 Args: 

301 read_cpg_states: Per-CpG methylation state values for a single 

302 read, in column-order, using the bam2tensor encoding 

303 (``1``=methylated, ``0``=unmethylated, ``-1``=no data). 

304 min_cpgs: Minimum number of CpG calls required to apply the 

305 filter. Reads with fewer calls are never flagged. 

306 

307 Returns: 

308 ``True`` when the read has at least ``min_cpgs`` CpG calls and 

309 every one of them is unmethylated (value ``0``). ``-1`` 

310 (no usable call) values are ignored. 

311 

312 Example: 

313 >>> is_em_overconversion_read([0, 0, 0], min_cpgs=3) 

314 True 

315 >>> is_em_overconversion_read([0, 0, 1], min_cpgs=3) 

316 False 

317 >>> is_em_overconversion_read([0, 0], min_cpgs=3) 

318 False 

319 >>> is_em_overconversion_read([0, 0, -1], min_cpgs=3) 

320 False 

321 >>> is_em_overconversion_read([0, 0, -1, 0], min_cpgs=3) 

322 True 

323 """ 

324 return read_cpg_states.count(0) >= min_cpgs and 1 not in read_cpg_states

327def detect_aligner(input_bam: str, sample_size: int = 1000) -> str: 

328 """Detect the aligner used to produce a BAM file by checking read tags. 

329 

330 Samples up to ``sample_size`` reads from the BAM file and checks for 

331 aligner-specific tags: ``XM`` (Bismark), ``YD`` (Biscuit/bwameth), 

332 or ``XB`` (gem3/Blueprint). 

333 

334 Args: 

335 input_bam: Path to an indexed BAM file. 

336 sample_size: Maximum number of reads to examine. Only primary, 

337 non-duplicate, non-QC-failed reads are considered. 

338 

339 Returns: 

340 A human-readable string identifying the detected aligner, such as 

341 ``"Bismark (XM tag)"`` or ``"Unknown"``. 

342 """ 

343 try: 

344 bam = pysam.AlignmentFile(input_bam, "rb", require_index=True) # type: ignore 

345 except (FileNotFoundError, ValueError): 

346 return "Unknown (could not open BAM)" 

347 

348 checked = 0 

349 for read in bam.fetch(): 

350 if read.flag & _SKIP_FLAGS: 

351 continue 

352 if read.has_tag("XM"): 

353 bam.close() 

354 return "Bismark (XM tag)" 

355 if read.has_tag("YD"): 

356 bam.close() 

357 return "Biscuit/bwameth (YD tag)" 

358 if read.has_tag("XB"): 

359 bam.close() 

360 return "gem3/Blueprint (XB tag)" 

361 checked += 1 

362 if checked >= sample_size: 

363 break 

364 

365 bam.close() 

366 return "Unknown (no XM/YD/XB tags found)"

369def check_chromosome_overlap( 

370 bam_references: tuple[str, ...] | list[str], 

371 embedding_chromosomes: list[str], 

372) -> None: 

373 """Check that BAM and embedding chromosome names overlap. 

374 

375 Detects the common mistake where a BAM file uses one chromosome naming 

376 convention (e.g., ``1``, ``2``, ``3`` from Ensembl) while the reference 

377 embedding uses another (e.g., ``chr1``, ``chr2``, ``chr3`` from UCSC). 

378 If no overlap is found but adding or stripping a ``chr`` prefix would 

379 create overlap, raises a clear error with guidance. 

380 

381 Args: 

382 bam_references: Tuple or list of chromosome/contig names from the 

383 BAM file header (e.g., from ``pysam.AlignmentFile.references``). 

384 embedding_chromosomes: List of chromosome names from the genome 

385 embedding (i.e., the expected chromosomes). 

386 

387 Raises: 

388 ValueError: If there is no overlap between BAM and embedding 

389 chromosome names, with a diagnostic message indicating 

390 whether a ``chr`` prefix mismatch is the likely cause. 

391 """ 

392 bam_set = set(bam_references) 

393 emb_set = set(embedding_chromosomes) 

394 

395 overlap = bam_set & emb_set 

396 if overlap: 

397 return 

398 

399 # Try adding "chr" prefix to BAM references 

400 bam_with_chr = {f"chr{name}" for name in bam_set} 

401 if bam_with_chr & emb_set: 

402 bam_example = next(iter(bam_set - emb_set)) 

403 emb_example = f"chr{bam_example}" 

404 raise ValueError( 

405 f"Chromosome name mismatch: BAM file uses '{bam_example}' " 

406 f"but the reference embedding expects '{emb_example}'. " 

407 f"Your BAM file appears to use Ensembl-style names (no 'chr' prefix) " 

408 f"while the embedding uses UCSC-style names ('chr' prefix). " 

409 f"Use --expected-chromosomes with matching names " 

410 f"(e.g., --expected-chromosomes '1,2,3,...')." 

411 ) 

412 

413 # Try stripping "chr" prefix from BAM references 

414 bam_stripped = {name[3:] for name in bam_set if name.startswith("chr")} 

415 if bam_stripped & emb_set: 

416 bam_example = next( 

417 name for name in bam_set if name.startswith("chr") and name[3:] in emb_set 

418 ) 

419 emb_example = bam_example[3:] 

420 raise ValueError( 

421 f"Chromosome name mismatch: BAM file uses '{bam_example}' " 

422 f"but the reference embedding expects '{emb_example}'. " 

423 f"Your BAM file uses UCSC-style names ('chr' prefix) " 

424 f"while the embedding uses Ensembl-style names (no 'chr' prefix). " 

425 f"Use --expected-chromosomes with matching names " 

426 f"(e.g., --expected-chromosomes 'chr1,chr2,chr3,...')." 

427 ) 

428 

429 # No overlap even with prefix changes -- completely different names 

430 bam_sample = sorted(bam_set)[:3] 

431 emb_sample = sorted(emb_set)[:3] 

432 raise ValueError( 

433 f"No overlapping chromosome names between BAM file and reference " 

434 f"embedding. BAM contains: {bam_sample}... " 

435 f"Embedding expects: {emb_sample}... " 

436 f"Ensure the reference FASTA matches the genome used for alignment " 

437 f"and that --expected-chromosomes is set correctly." 

438 )

441def check_chromosome_lengths( 

442 bam_lengths: dict[str, int], 

443 reference_lengths: dict[str, int], 

444) -> None: 

445 """Check that the BAM was aligned to chromosomes of the reference's lengths. 

446 

447 A BAM records the length of every sequence it was aligned to. If a 

448 chromosome has one length there and another in the reference FASTA the 

449 CpG index was built from, the two are different assemblies (hg19 and 

450 hg38, say) that merely share chromosome names. Positions do not 

451 correspond between them, so the reads would be decoded at positions 

452 that are not CpGs in the genome they were aligned to. 

453 

454 Only chromosomes present under the same name on both sides are 

455 compared. 

456 

457 Args: 

458 bam_lengths: Sequence name to length, from the BAM header. 

459 reference_lengths: Chromosome name to length, from the reference 

460 FASTA (``GenomeMethylationEmbedding.chromosome_lengths``). 

461 

462 Raises: 

463 ValueError: If any shared chromosome differs in length. 

464 

465 Example: 

466 >>> check_chromosome_lengths({"chr1": 1000}, {"chr1": 1000, "chr2": 500}) 

467 """ 

468 mismatched = [ 

469 (name, bam_lengths[name], length) 

470 for name, length in reference_lengths.items() 

471 if name in bam_lengths and bam_lengths[name] != length 

472 ] 

473 if not mismatched: 

474 return 

475 shown = ", ".join( 

476 f"{name} ({bam_length:,} bp in the BAM, {length:,} bp in the reference)" 

477 for name, bam_length, length in mismatched[:3] 

478 ) 

479 if len(mismatched) > 3: 

480 shown += f", ... ({len(mismatched)} chromosomes in total)" 

481 raise ValueError( 

482 "The BAM file was not aligned to the reference FASTA provided: " 

483 f"chromosome lengths differ for {shown}. Positions do not correspond " 

484 "between two different assemblies, so the methylation calls would be " 

485 "wrong. Use the reference the BAM was aligned to. (If the FASTA is a " 

486 "deliberately truncated copy of that reference, the check can be " 

487 "turned off with --allow-length-mismatch.)" 

488 )

561class _ExtractionConfig(NamedTuple):

638# Strand-tag check (Biscuit / bwameth / gem3 reads, which are decoded from 

639# their bases on the strength of the aligner's strand tag). 

640# 

641# A read reports on one strand, so only one base of each CpG can show a 

642# conversion: the C for a top-strand fragment, the G for a bottom-strand one. 

643# The CpG's other base is never converted. Seeing that other base converted 

644# (an A at the G of a read tagged top strand, a T at the C of a read tagged 

645# bottom strand) contradicts the tag. In correctly tagged data that only 

646# happens through sequencing errors and CpG SNPs — a fraction of a percent of 

647# CpGs. Wrongly tagged reads show it at every unmethylated CpG, which is what 

648# happens to most complementary-strand pairs when a non-directional library is 

649# aligned by an aligner that assumes a directional one (bwa-meth). 

650# 

651# A BAM is flagged when more than this fraction of the CpGs checked contradict 

652# their read's tag... 

653_STRAND_CONTRADICTION_WARNING_RATE = 0.02 

654# ...provided at least this many CpGs were checked, so that a handful of 

655# errors in a small BAM cannot trigger the warning. 

656_STRAND_CHECK_MIN_CPGS = 1000 

657 

658# How far downstream (in bp) a read's mate may start and still be combined 

659# with it into one fragment. Reads are processed in coordinate order and rows 

660# are written in the order fragments first appear, so a fragment waiting for 

661# its mate holds back every fragment behind it. Real inserts are a few hundred 

662# bases; this generous cap only bounds how long a far-flung (chimeric or 

663# mis-annotated) pair can make the queue grow. Mates further apart than this 

664# are reported as two separate fragments. 

665_MAX_MATE_DISTANCE = 100_000 

666 

667# Two of the default filters act on what the BAM says about itself: the 

668# proper-pair flag and the base qualities. A BAM that does not carry them in 

669# the usual way (an aligner that never sets the flag; placeholder qualities) 

670# would have most of its data discarded without a word. A BAM is flagged when 

671# more than this fraction of its otherwise usable reads are dropped as 

672# improper pairs, or of its otherwise usable CpG calls for low base quality... 

673_FILTER_MAJORITY_WARNING_RATE = 0.5 

674# ...provided at least this many reads, or calls, were dropped. 

675_FILTER_MAJORITY_MIN_COUNT = 1000

678# ends_seen in _extract_chromosome) are kept before those whose other mate 

679# never arrived are discarded.

682# Key under which no fragment is ever filed while awaiting its mate (see

686# Reference check. Wherever a read covers a CpG of the reference, the read is 

687# expected to show a CpG too: at the base carrying the call, the methylated 

688# or the unmethylated base; at the other base, the reference base. Sequencing 

689# errors, SNPs and indels break this at a percent or two of CpGs. A BAM 

690# decoded against a reference it was not aligned to breaks it at most of 

691# them, because the positions taken to be CpGs are arbitrary positions of the 

692# genome the reads were really aligned to.

765 >>> _three_prime_end(100, 200, 200, False, None, True)

925def _merge_mate_calls( 

926 cols: list[int], 

927 data: list[int], 

928 mate_cols: list[int], 

929 mate_data: list[int], 

930) -> tuple[list[int], list[int]]: 

931 """Combine the CpG calls of a fragment's two mates. 

932 

933 Mates that overlap report some CpGs twice. Those are the same bases of 

934 the same molecule read twice, so they are recorded once: 

935 

936 - if both mates make the same call, that call is kept; 

937 - if only one mate has a call (the other has ``-1``), that call is kept; 

938 - if the mates disagree (one methylated, one unmethylated), at least one 

939 is a sequencing error and there is no telling which, so the CpG is 

940 recorded as ``-1`` (no data). 

941 

942 Args: 

943 cols: Matrix columns called by the first mate, ascending. 

944 data: Methylation state for each entry of ``cols``. 

945 mate_cols: Matrix columns called by the second mate, ascending. 

946 mate_data: Methylation state for each entry of ``mate_cols``. 

947 

948 Returns: 

949 The merged columns, ascending, and the state for each. 

950 

951 Example: 

952 >>> _merge_mate_calls([3, 4], [1, 0], [7, 8], [1, 1]) 

953 ([3, 4, 7, 8], [1, 0, 1, 1]) 

954 >>> _merge_mate_calls([3, 4, 5], [1, -1, 0], [4, 5, 6], [1, 1, 0]) 

955 ([3, 4, 5, 6], [1, 1, -1, 0]) 

956 """ 

957 # Common case: the mates do not overlap at any CpG. 

958 if cols[-1] < mate_cols[0]: 

959 return cols + mate_cols, data + mate_data 

960 if mate_cols[-1] < cols[0]: 

961 return mate_cols + cols, mate_data + data 

962 

963 merged = dict(zip(cols, data)) 

964 for col, state in zip(mate_cols, mate_data): 

965 seen = merged.get(col) 

966 if seen is None or seen == -1: 

967 merged[col] = state 

968 elif state != -1 and state != seen: 

969 merged[col] = -1 

970 merged_cols = sorted(merged) 

971 return merged_cols, [merged[col] for col in merged_cols]

1654 unmethylated CpG fails the intact-CpG rule and is recorded as 

1655 ``-1``, so only methylated calls survive and methylation is 

1656 overstated. With ``verbose=True`` the counts are printed for every 

1657 BAM. 

1658 

1659 **Reference check.** The BAM must have been aligned to the reference 

1660 the CpG index was built from. Chromosomes whose length in the BAM 

1661 header differs from the reference raise a ``ValueError`` (unless 

1662 ``allow_length_mismatch``). Independently, if more than 10% of at 

1663 least 1,000 decoded CpGs mismatch the reference in their read, a 

1664 ``RuntimeWarning`` reports it: real data stays within a few percent, 

1665 while a BAM decoded against the wrong reference fails at most CpGs. 

1666 (CpGs whose only fault is the other strand's conversion product at 

1667 the CpG's other base are left to the strand-tag check.) 

1668 

1669 **Filters that depend on the BAM's own annotations.** The proper-pair 

1670 and base-quality filters trust the flag and the qualities in the 

1671 BAM. If more than half of the otherwise usable reads are dropped as 

1672 improper pairs, or more than half of the otherwise usable calls for 

1673 low base quality (at least 1,000 in either case), a 

1674 ``RuntimeWarning`` says so and names the option that turns the 

1675 filter off. 

1676 

1677 Args: 

1678 input_bam: Path to the input BAM file. The file must be indexed 

1679 (have a corresponding .bam.bai file). 

1680 genome_methylation_embedding: A GenomeMethylationEmbedding object 

1681 that defines the CpG site positions and provides coordinate 

1682 conversion methods. 

1683 quality_limit: Minimum mapping quality (MAPQ) threshold for reads. 

1684 Reads with MAPQ below this value are skipped. Default is 20, 

1685 which excludes reads mapping to multiple locations equally well. 

1686 filter_non_converted: If True, drop fragments in which a read 

1687 carries at least ``non_converted_threshold`` retained non-CpG 

1688 cytosines, a signature of incomplete bisulfite/EM-seq 

1689 conversion. Default False. 

1690 non_converted_threshold: Minimum count of retained non-CpG 

1691 cytosines required for the non-converted filter to drop a 

1692 read. Matches the NEB ``mark-nonconverted-reads`` default of 

1693 3. 

1694 filter_em_overconversion: If True, drop fragments whose CpG 

1695 calls are all unmethylated and number at least 

1696 ``em_overconversion_min_cpgs`` — the Loyfer et al. EM-seq 

1697 fragment-level over-conversion heuristic. Default False. 

1698 em_overconversion_min_cpgs: Minimum number of CpG calls required 

1699 before the over-conversion filter will drop a fragment. Matches 

1700 the regime in Loyfer et al. Fig. 1C where the EM-seq 

1701 artifact is clearly separable from WGBS. 

1702 threads: Number of worker processes to use, one chromosome per 

1703 worker. Default 1 (in-process, no IPC overhead). Values 

1704 above 1 fan out per-chromosome extraction across worker 

1705 processes; output is bitwise-identical to ``threads=1`` 

1706 because per-chromosome results are concatenated in 

1707 ``cpg_sites_dict`` order, whatever order the workers finish 

1708 in. Each worker is sent only the CpG positions of the 

1709 chromosome it is processing, not the whole embedding. 

1710 Recommended: leave at 1 for small BAMs (worker 

1711 startup dominates); set to the number of physical cores 

1712 for whole-genome WGBS BAMs. Workers are started with the 

1713 ``spawn`` method, so a script that passes ``threads > 1`` 

1714 must do so from under ``if __name__ == "__main__":`` 

1715 (standard :mod:`multiprocessing` practice). 

1716 verbose: If True, display a progress bar and print the total read 

1717 count. Useful for monitoring progress on large files. 

1718 debug: If True, print the calls decoded from every read and 

1719 each filter decision. Significantly slower. 

1720 min_base_quality: Minimum Phred base quality of the base that 

1721 carries a CpG call. Calls on lower-quality bases are 

1722 recorded as ``-1``. Default 20; 0 disables the filter. Reads 

1723 stored without base qualities are never filtered. 

1724 mask_3prime: Number of bases at the 3' end of each fragment's 

1725 original strand in which calls are recorded as ``-1``, to 

1726 remove the end-repair fill-in artifact. The end is the 

1727 fragment's right-hand end for a top-strand fragment and its 

1728 left-hand end for a bottom-strand one, taken from the 

1729 alignment of the mate that starts there; a read whose mate 

1730 is not available estimates it from the template length, and 

1731 a single-end read uses its own end. The distance is measured 

1732 on the aligned fragment, so bases already trimmed from the 

1733 reads before alignment are not counted. Default 0 (off). 

1734 keep_improper_pairs: If True, keep paired reads that are not 

1735 flagged as a proper pair. Default False. 

1736 allow_length_mismatch: If True, do not require the chromosome 

1737 lengths in the BAM header to match the reference. Only for 

1738 a reference that is a deliberately truncated copy of the one 

1739 the BAM was aligned to. Default False. 

1740 

1741 Returns: 

1742 An ExtractionResult named tuple with three fields: 

1743

1745 (n_fragments, n_cpg_sites) where n_fragments is the number of 

1746 fragments that passed filters and covered at least one CpG

1760 

1761 Raises: 

1762 FileNotFoundError: If the BAM file index (.bam.bai) is missing.
